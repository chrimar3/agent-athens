# S177 checkpoint — performer-sameAs.json QID fabrication (follow-up brief needed)

**Found en route during the neighborhood-QID sweep (2026-06-05).** Out of S177's boundary; checkpointed with evidence.

## The defect

`config/performer-sameAs.json` (generated by `scripts/lookup-performer-sameAs.ts`) pairs **correct Wikipedia URLs with fabricated Wikidata QIDs** — the generator resolves the Wikipedia title correctly, then invents the QID. Spot-verified examples:

| Performer | Wikipedia link (correct) | QID emitted (wrong) |
|---|---|---|
| Αλκίνοος Ιωαννίδης | en.wikipedia.org/wiki/Alkinoos_Ioannidis | **Q379849 = Qazi Muhammad, founder of the Republic of Mahabad** |
| Villagers of Ioannina City | …/Villagers_of_Ioannina_City | **Q20649047 = Archery at the 2015 European Games** |
| Rotting Christ | …/Rotting_Christ | **Q685757 = Rebellion of the Alpujarras (1568)** |

Batch label-check of all 62 unique QIDs across performer-sameAs + venue sameAs: **venue QIDs all verified correct** (human-curated, Wikipedia cross-refs); performer set contains ≥17 hard-wrong entities (hurricane season, Little Albert experiment, villages in China/Iran/Poland/Norway, UNESCO Weimar, Wikimedia category, disambiguation page, 1962 painting, cycling race, academic article, boxer, 4 missing/deleted entities, ancient-homonym Leon of Athens) plus plausible-but-unowned matches needing per-performer confirmation. **Emitted live** on event pages via `getPerformerSameAs` (event-page.ts:41) — spot-check found 7+ dist pages.

## Fix path for the follow-up brief

1. **Deterministic re-derivation, no lookup model:** for each entry, take the existing (correct) Wikipedia URL and query `en.wikipedia.org/w/api.php?action=query&prop=pageprops&ppprop=wikibase_item&titles=<title>` — Wikipedia returns the authoritative QID. Replace all 62; drop QIDs where no Wikipedia link exists to derive from (absence beats fabrication).
2. **Patch the generator** (`scripts/lookup-performer-sameAs.ts`) to derive QIDs the same way — never emit a QID that didn't come from the wikibase_item pageprop.
3. **Paired validator** (S110 pattern): emitted wikidata sameAs URIs must exist in the (re-derived) cache; consider a periodic label-spot-check script.
4. Stale-dist sweep after the fix (S176/S177 lesson: never-regenerated venue/event pages keep old QIDs).

## Why this class keeps appearing (for decisions.md)

Three corruption surfaces, one cause: **LLM-fabricated QIDs committed without entity-resolution against Wikidata** (neighborhood-geodata: 13/13 wrong; city-geodata: Attica = David Gilmour; performer-sameAs: ≥17 wrong). QIDs are plausible-format identifiers — the failure is silent until something resolves them. Rule going forward: **a QID may only enter config via a resolver output (wbgetentities/wbsearchentities/pageprops), never via generation.**
