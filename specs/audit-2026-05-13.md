### P0 — `price_type='tba'` regression (Tier 1 violation, actively regenerating)

- **Symptom:** 42 rows back, all from one source (residentadvisor), all written by today's pipeline.
- **Root cause hypothesis (not yet confirmed):** `src/db/database.ts:92` is the only call site of `normalizePriceType()`. Other write paths exist:
  - `src/ingest/email-ingestion.ts:322` — a parallel `upsertEvent()` with its own `UPDATE events SET …`
  - `src/images/image-pipeline.ts:34` — direct `UPDATE events …`
  - Possibly a residentadvisor scraper-side raw write (not confirmed; needs grep beyond audit scope).
- **Blocks:** B-04 (S137 offers refactor) — clean type/writer/data state was its declared precondition.
- **Unblock path:** Identify the bypass path → add `normalizePriceType()` call (or route through canonical `upsertEvent`) → re-migrate the 42 rows → add validator rule (B-03) so the next regression fails CI rather than ships.

- Per `s126-state-audit-2026-05-08.md` and confirmed today: zero Παναθήναια events in DB.
- 16 days until demo.
- **Unblock path:** source survey → first-source scraper or hand-seed → enrichment for the demo events specifically.

- `isPlaceholder()` doesn't read `price_type`. Had it done so, the residentadvisor regression would have failed S136's `bun run build` rather than shipping silently.
- Not a *forward* blocker but the **detective-control gap** that allowed P0 #1 to reach production. Closing it before B-01's data fix would have caught the bypass with a test.
