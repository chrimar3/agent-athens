# S176 follow-up — comedy-format leak on the category-page surface (NOT yet tripwired)

**Status:** Open. Surfaced during S176 (2026-06-09), scoped OUT of the locked
brief (hubs only), escalated here as a ready-to-run session.
**Priority:** HIGHER than a normal backlog item — this surface is **NOT guarded
by the S110 invariant** (see "Why this can't wait" below).

## Context

S176 re-keyed /theatre + /comedy **hub** membership (`config/hub-pages.json` +
`getHubEvents`, `src/generators/hub-page.ts`) to the comedy-format signal
(`isStandUpComedy`, `src/utils/comedy-format.ts`) and shipped a build-halting
S110 subset invariant on the **theatre hub** (`dist/theatre.html`,
`dist/en/theatre/index.html`).

The **category-page** surface carries the **same latent leak** through a
**different predicate** the brief's recon did not reach: a theatre-typed
stand-up appears on the theatre category pages by `event_type`, exactly as it
did on the hub before the re-key.

## The leaking predicate

- **`filterEventsByCategory(events, category)`** — `src/templates/category-page.ts:30`.
  Pure `event.type` / genre filter, **no comedy-format awareness**:
  ```
  if (category.filter.types?.length) { if (!types.includes(event.type)) return false; }
  else if (category.filter.type && event.type !== category.filter.type) return false;
  ```
- Driven by **`config/categories.json`** — the `theatre` category (slug
  `theatre`, line ~56) filters `"type": "theater"`. A `type=theater` stand-up
  (`@type=ComedyEvent`) therefore lists on every theatre category page.
- Generated by **`generateCategoryPages()`** — `src/generate-site.ts:1415`
  (calls `filterEventsByCategory` at :1435).
- **Also consumed by `src/generators/search-index.ts:128`** — re-keying the
  predicate changes the search index too (wider blast radius than the hub fix;
  account for it).

## Affected dist files (~13)

Pure theatre category (stand-ups should be EXCLUDED):
`theater-today.html`, `theater-tomorrow.html`, `theater-this-week.html`,
`theater-this-weekend.html`, `theater-this-month.html`, `theater-next-month.html`
(+ the `en/` mirrors).

Combined comedy+theater category (stand-ups should STAY — it is the joint
surface): `comedy-theater.html`, `comedy-theater-{today,tomorrow,this-week,
this-weekend,this-month,next-month}.html`. **Do NOT exclude comedy-format from
the combined category** — only the pure `theatre` category.

## The fix (same mechanism as S176, fully specified)

1. Re-key only the pure `theatre` category to exclude comedy-format. Cleanest:
   add an opt-in flag to `CategoryConfig` (mirror the hub's `comedyFormat?:
   'exclude' | 'include'`), set the `theatre` category to `exclude` in
   `config/categories.json`, and apply `!isStandUpComedy(e)` as a post-filter in
   `filterEventsByCategory`. Reuse `isStandUpComedy` — do not reimplement.
   The `comedy` category (if it lists by tag) gets `include` like the hub.
   Leave the combined `comedy-theater` category untouched.
2. Verify the search index (`search-index.ts:128`) reflects the same membership.
3. Precision guard (same as S176): exclude on the POSITIVE `isStandUpComedy`
   match only — circus/variety/magic/drag stay in the theatre category.

## Tripwire (do this WITH the fix, never before)

Extend the S110 subset invariant to the theatre category pages: register the
theatre category dist files in `validateAllPages`' walk and apply the same
`THEATRE_ELIGIBLE_TYPES` subset assert + the `S110_THEATRE_COMEDY_LEAK` hard-stop.

**LANDMINE WARNING:** the category pages list comedy-format events **today**.
Arming the tripwire on them BEFORE re-keying the predicate would halt the build
immediately (the exact "fix + tripwire ship together" hazard from S176). Ship
the predicate re-key and the tripwire extension in the **same** change.

## Why this can't wait

After S176, the hub surface is both fixed AND tripwired (a regression halts the
build). The category surface is **fixed nowhere and tripwired nowhere** — the
leak is live there today (lifecycle-masked, same as the hub was), with no build
gate to catch its re-exposure. That makes it a silent latent bug, not a dormant
one. Schedule promptly.
