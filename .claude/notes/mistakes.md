# Common Mistakes

Pitfalls encountered and how to avoid them.

## Database

| Mistake | What Happened | Correct Approach |
|---------|---------------|------------------|
| Missing created_at default | SQLite NOT NULL constraint failed when scraper didn't set date | Always provide defaults in `eventToRow`: `event.createdAt \|\| new Date().toISOString()` |
| Deleting running exhibitions | `cleanupOldEvents` used start_date for all events | Use `COALESCE(CASE WHEN type='exhibition' THEN end_date ELSE NULL END, start_date)` |
| Filtering out current exhibitions | Site generation used `startDate >= today` for exhibitions | Check `endDate >= today` for exhibitions |
| DB string-column format non-uniformity (2nd instance, see S43) | `events.start_date` stored in 3 inconsistent shapes: `date-only`, `naive-ts`, `tz-aware` (`+03:00`). `GROUP BY start_date` fragmented single days into many rows; filter/sort worked only by lexicographic luck. S43 was a similar pattern (price_type values), S95 is the second. | Enforce canonical format at every write seam via `normalizeDateField()` (`src/utils/date-format.ts`). Migrate existing rows once (`scripts/migrate-date-format.ts`). Guard future bypasses with `tests/no-bypass.test.ts`. Render-time DST offset is layered back on via `formatSchemaDate()`, never stored on-disk. |
| DB abstraction bypass pattern — raw INSERT outside the ORM/upsert seam | Scrapers ran `db.prepare('INSERT INTO events …')` for batching throughput. The format-normalization guarantee of `upsertEvent()` was lost. Mixed formats accumulated across 3 scraper sources (scrape-all, scrape-snfcc, scrape-ai-tech). Also surfaced a 4th site in `email-ingestion.ts` that wasn't really a bypass — it was broken dead code writing to non-existent columns. | Mitigation: explicit allowlist of accepted bypasses with line-range + justification comment per entry (`tests/no-bypass.test.ts` `ALLOWED_BYPASSES`). Each allowlisted writer **must** call `normalizeDateField()` at bind time. Adding a new bypass is the exceptional case, not the default — the test fails loudly if a new INSERT appears outside the list. |
| Dead code ≠ design-by-bypass | Tempted to allowlist `src/ingest/email-ingestion.ts:360` (a 4th `INSERT INTO events` site) alongside the 3 legitimate scraper bypasses. But that INSERT was broken — it wrote to non-existent columns (`date, time, venue, …`) and would have thrown at runtime if reached. Allowlisting would have inverted the test's meaning: "this bypass is accepted" vs. the actual truth "this bypass is broken." | Broken bypass code belongs in a `throw` referencing the resolution session, OR in deletion. Never the allowlist. Precedent: `src/ingest/email-ingestion.ts:360` now `throw new Error('email ingestion: date/time schema deprecated; pending Session C unification')`. The throw preserves the loudness of the failure without polluting the seam guard. |
| **Enumerate by value shape, not just value source** (Guard 6 grep-pattern miss) | Session A plan's Guard 6 enumeration greps looked for `start_date\|end_date\|startDate\|endDate` — column and property names. This caught DB reads and property access but MISSED three render sites (`event-page.ts:159`, `venue-page.ts:107`, `templates/page.ts:386`) that inline-constructed Schema.org date strings like `${date}T00:00:00${tz}` without reading the property directly. Fixing `formatSchemaDate()` alone produced a pipeline that looked correct (tests passed, validator passed) while still emitting the live bug at 2/3 of event page rendering paths. The miss was only caught post-build by grepping dist output for the pinned spot-check ID. | When enumerating consumers of a column/value for a cross-cutting refactor, grep for **both** (a) the value source — `column_name`, `propertyName`, DB/API field references — AND (b) the value shape — literal substrings that inline-construct the same value without reading the source. For dates: add `T00:00:00`, hardcoded offsets (`+03:00`/`+02:00`), Schema.org key patterns (`"startDate"`, `"endDate"`). For URLs: `href=`, template literals building paths. For money: currency symbols, price-string construction. Named check for Planner rubric: **"Enumerate by value shape, not just value source."** |
| Validators can codify bugs; their agreement is not proof of correctness | `src/validators/schema-completeness.ts` enforced "startDate must end with `[+-]HH:MM\|Z`" — a constraint *stricter* than Schema.org actually requires (Schema.org accepts date-only for all-day events). The validator agreed with the buggy render code (which always emitted offsets, including wrong midnight-timestamps for date-only exhibitions). Both agreed internally; both disagreed with the spec. Self-consistency is not correctness. | When tightening a canonical format on the write side, grep for sibling validators that may have codified the pre-existing (buggy) shape as their invariant. Loosening the validator is often part of the fix, not a regression. Review questions: does this validator assert what the spec requires, or what our current emitter happens to produce? If the latter, the validator is a mirror of behavior, not a guard against it. |
| Commit scope is not what `git status` says, it's what the index holds | S95 commit `f580df806` silently included 3 monitor-extension files I hadn't intended to stage for Session A. Searched every plausible hook location (`.git/hooks/`, `.husky/`, `core.hooksPath`, Claude Code `settings.json` at both scopes, plugin configs) — no hook exists. Likely cause: an earlier `git add .` or `git add -A` during the session staged the monitor files; subsequent `git add <specific-paths>` calls added more files without unstaging them. `git status --short` right before commit still showed them as `??` / ` M` in the *working-tree* view, but the *index* already held them. A bare `git commit` with no path args commits the index, not what `git status` displays. Required a reset + resplit to un-bundle. | Before every `git push`, run `git show --stat HEAD` (or `git show --stat origin/main..HEAD` for multi-commit work). Compare file count and approximate line-count against the session's Critical Files list. If they don't match, stop and investigate before pushing — rewriting unpushed commits is cheap, rewriting pushed commits breaks everyone's clone. Named check: **"verify commit scope with `git show --stat HEAD` between commit and push, not `git status` before commit."** |

| Mistake | What Happened | Correct Approach |
|---------|---------------|------------------|
| Wrong event type for scraped data | SNFCC events typed as "other" | Explicitly set `type: 'exhibition'` in scraper |
| Scroll lock race condition | Filter bar and hamburger menu both set `body.style.overflow` directly — closing one unlocked scroll while the other was still open | Use independent CSS classes (`scroll-locked` / `scroll-locked-menu`) so each component locks/unlocks independently |
| Redundant "all-events" option in date panel | "Όλες 891" linked to `/` on the homepage — a dead link to the page the user is already on | Removed from `TIME_OPTIONS`; dismiss `×` on active date pills already clears the time filter |
| data-slug format divergence in save feature | Card save buttons on browse page stored `data-event-slug="/events/abc-123/"` (full path via `href`) while event detail page stored bare slug `"abc-123"`. The /saved/ page prepends `/events/` → double prefix → 404. Root cause: `prepareCardData` returned `href` but not `slug`. | Always emit raw identifiers in `data-*` attributes. ## URL structure — hub pages are root-level, not nested

Greek hubs: `/{slug}/` (e.g. `/today/`, `/sabbatokyriako/`)
English hubs: `/en/{slug}/` (e.g. `/en/today/`, `/en/this-weekend/`)

NOT `/events/{slug}/` or `/en/events/{slug}/` — that path pattern doesn't exist.

When diagnosing a 404 on any hub-related URL, first verify the URL itself is correct
before assuming a generator/routing bug. Check `ls dist/{path}/` to confirm the
expected file location before investigating further.
